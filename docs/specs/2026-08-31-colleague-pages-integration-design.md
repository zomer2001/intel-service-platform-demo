# 同事业务成果页面整合设计

## 目标

将 `lattice-intelligence-local 4` 中“技术发展态势研判”和“技术辅助还原与破解”的全部 8 个页面及二级交互，原生迁移到当前 `demo-html/`。保留现有纯 HTML、CSS、原生 JavaScript 架构和 `file://` 运行能力，不带入同事工程自己的侧栏、顶栏和一级导航。

## 信息架构

- 新增 `pages/applications/trends.html`，四个单行 Tab：前沿技术动态监测、技术领域总体趋势、关键技术路线演化、关键技术差距分析。
- 新增 `pages/applications/restoration.html`，四个单行 Tab：业务场景推演方案集、技术原理拆解图谱、开源项目索引矩阵、仿真验证参数包。
- Tab 使用 `?tab=` 保存当前选择，切换时不重载 AppShell。
- 态势研判页当前对象为 `Lattice`，显示“平台级分析”；辅助还原页当前对象为 `Lattice Mesh`，显示“技术级分析”。
- 更新左侧两个业务入口的跳转；现有任务中心、产品技术谱系、三级任务页和三项关键技术页保持不变。

## 视觉与交互

- 统一使用现有品牌区、左侧导航、顶部栏、视觉 Token、Card、Button、Table、Tab 和 Drawer 风格。
- 完整保留筛选、排序、对象详情、证据与报告详情、报告下载、版本时间轴、路线节点、图谱节点、拆解树、项目索引联动、项目详情子 Tab、开源项目发现和参数处理过程。
- 对象、证据、报告、版本、节点、项目和参数详情统一在右侧 Drawer 展示。
- 页面主体不产生横向滚动；仅图谱和拆解树等确实超宽的内容可在卡片内部滚动。
- 正式界面不出现 `Demo`、`演示` 等措辞；统一使用“样例研判数据／公开资料研判，仅供分析参考”。

## 数据与运行方式

- 将同事工程两份 JSON 数据转换为普通 JavaScript 数据文件，通过全局只读对象加载，避免 `file://` 下 `fetch` 受限。
- 不联网、不随机。动态发现和参数处理按固定步骤线性推进；切换 Tab 后继续运行，返回时显示实际进度。
- 报告和参数包在浏览器本地生成下载文件。
- 同事数据中的非真实项目地址保留为“样例地址”，不将其表述为已核验外部链接。
- 不引入新框架、自动测试体系或复杂全局状态机。

## 完成标准

- 8 个 Tab 均可通过正式业务入口访问，刷新后保留当前 Tab。
- 所有约定的二级交互可用，Drawer、下载和动态过程工作正常。
- 左侧导航可在任务中心、产品技术谱系、态势研判和辅助还原之间往返。
- 正式界面无开发或录屏措辞。
- Chrome/Edge 通过本地页面运行时无明显控制台错误。

## 范围边界

- 不修改同事工程原目录。
- 不修改现有三级任务状态机、关键技术页面、EvidenceDrawer、WorkflowDrawer 和品牌视觉。
- 不扩展新的业务内容，也不引入真实联网数据。
