# Lattice 持续监测详情原版恢复设计

## 目标

保留当前情报服务平台的左侧导航、顶部信息栏、页面标题和四个业务 Tab，只恢复 `前沿技术动态监测 → Lattice` 详情正文的原版内容结构与排版。用户进入后应获得与同事原版相同的信息层级和左右布局，同时仍感觉处于当前统一平台中。

## 修改边界

- 仅修改 Lattice 专属详情视图及对应样式。
- 不修改监测对象列表、另外三个业务 Tab、左侧导航、顶部栏和公共组件。
- 不修改 `file://` 运行方式，不增加框架、网络请求或测试工程。
- 当前平台的颜色、字体和按钮 Token 保留；正文区块的尺寸、顺序、比例和交互按原版恢复。

## 正文结构

1. 顶部保留“返回监测对象列表”。
2. 使用原版对象横幅：Lattice、重点监测、软件体系、技术状态、最新版本、双驱动监测状态。
3. 五项指标保持一行：累计资料、近 30 日新增、有效事件、高价值事件、报告生成机制。
4. 主区域恢复原版左右结构：
   - 左侧为 2026 年双轨时间轴，红色突发事件在上、蓝色报告版本在下，并显示版本差异摘要。
   - 右侧为多源新增情报流，展示资料发现、事件识别、关联融合和态势更新，以及近期报告版本。
5. 底部恢复两列：当前差异化态势摘要、研判成果联动。

## 交互

- 点击 Lattice 整行进入详情，返回按钮回到对象列表。
- 点击事件打开现有事件与证据抽屉。
- 点击报告卡或差异摘要打开报告详情，已生成版本可下载，计划版本不可下载。
- 多源情报流按原版自动运行，也可点击重新执行。
- “关键技术路线”和“关键技术差距”使用现有 Tab 切换，不重载 AppShell。
- `?tab=monitor&view=lattice` 继续支持直接访问。

## 数据与措辞

- 使用已经迁入的 Lattice、Event、Source 数据。
- 报告版本、差异摘要和流程阶段严格恢复同事原版内容。
- 正式界面统一使用“样例研判数据／公开资料研判，仅供分析参考”，不恢复“演示”措辞。

## 完成标准

- 1920×1080 下主体呈现原版左右布局，五项指标为一行。
- 报告时间轴、事件、报告详情、下载、流程执行和成果联动均可操作。
- 返回列表和直接 URL 正常。
- 另外三个 Tab 和公共 AppShell 无变化。
- JavaScript 语法、相对资源和 `file://` 兼容性检查通过。
